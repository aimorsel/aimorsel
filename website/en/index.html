For agents

Let the agent go look it up

A built-in MCP server: one line to register, eight tools. Documents stay on your machine; the agent takes only what it needs.

# register (Claude Code)
$ claude mcp add aimorsel -- morsel mcp

# what the agent then does on its own
get_outline("annual-report.pdf")
get_section("annual-report.pdf", "Financial summary")
search_documents("gross margin")

Batch

A thousand documents, unattended

Power cut, a late addition, picking it up the next morning — it carries on where it left off.

Resumable
Converts only what's new or changed; a different output format re-runs everything
Parallel workers
Noticeably faster past a few dozen files; one bad file doesn't stop the batch
Watched folder
Drop a file in and it converts; still-copying files are left alone until they settle
Run report
One CSV per batch: status, pages, duration, reason for failure. Opens in Excel
A floor under failure
Files the engine can't parse fall back to plain text extraction rather than an empty folder

Our own benchmark

The numbers are in the repo, and you can recompute every row

731 public documents × 5 engines = 3,224 records. Ground truth is parsed from the source files themselves (arXiv LaTeX sources, the HTML editions of statutes, the known structure of generated files) — no human scoring, no LLM as judge.

Engine Accepts Converted out of 731 Text similarity (docs both converted, them / us) Median time
AImorselall 8 format classes731 (100%)—1.6 s/doc
doclingcomparable to ours299 / 300 (stratified subset)0.841 / 0.83911.2 s/doc
pymupdf4llmPDF only293 (40%)0.775 / 0.7737.2 s/doc
markitdownmost formats except images and scans539 (74%)0.715 / 0.8420.8 s/doc
pdfplumberPDF only, plain text289 (40%)0.574 / 0.7780.5 s/doc

Unsupported formats count as failures — that column answers “drop a mixed folder in, how much comes out”. Text fidelity is a tie with docling and pymupdf4llm; runtime differs by an order of magnitude (docling peaks at 2.0 GB p95, we peak at 620 MB). One silent failure only we and docling avoid: markitdown and pdfplumber emit ten Arabic documents in visual order — every character present, but search and tokenization broken.

Two things have to be said plainly. docling takes ~11 s per document, too slow for the full run, so it only covers a 300-document stratified subset and its row is not a like-for-like count. And on the 77 documents every engine converted, docling and pymupdf4llm beat us on text similarity (0.92 / 0.92 against 0.82) — that subset is small and skewed toward plain single-column PDFs, and we lead on the structure metrics in that same table. Both tables are published. Our weakest link is scans and images: digit fidelity is 0.891 on documents with a text layer but 0.716 through the OCR channel, so numbers read off a scan are good for locating a figure, never for putting straight into a spreadsheet.

Full result tables and reading caveats → The corpus manifest, download scripts, ground-truth generators, metric implementations and batch runner all live in bench/; rerunning the same manifest reproduces the numbers within 1%.

Download

Unzip. That's the whole install.

A trimmed Java runtime ships inside, so there's no Java and no Python to install.

One package holds the command line, the desktop app, the web service and the MCP server, sharing a single set of dependencies. Developers can pip install aimorsel or install from source instead — see the download page.

The open-source core stays free, complete and local. Always. Formula → LaTeX and handwriting recognition are being built as an optional local model pack — also offline.
