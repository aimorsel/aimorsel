# 人工抽检（60 份）—— 判读与失败模式

> 2026-08-18 夜跑 E 阶段。按 `format × lang` 分层随机抽 60 份（种子 20260818），
> 覆盖 8 种格式、8 种语言、12 个来源，其中图片/scan-pdf 22 份、`truth_type=C`（无精确真值）11 份，
> 并特意纳入指标异常样本（char_sim < 0.5、cell_f1 = 0、status ≠ ok）。
> 判读用 PLAN §3.4 的 rubric（内容完整 / 结构正确 / 表格可用 / 顺序通顺 / 无乱码，各 1–5 分）。
>
> **本文件放在 `bench/` 而不是 `bench/results/`**：后者整个在 .gitignore 里，
> 判读结论是要随仓库走的东西，不该跟着原始结果一起被忽略。
>
> ⚠️ 判读时引用的 char_sim / cjk_inner_spaces 数值取自抽检当时的快照。抽检**过程中**
> 发现并修掉了两个指标 bug（见文末），全部结果已 `bench/rescore.py` 重算，
> 因此 `RESULTS.md` 里的数字与个别引文会有出入；**定性结论不受影响**。

## 一、总体结论

抽检最有价值的产出不是分数，而是**三条自动指标完全看不见的缺陷**，以及**四类「分数低但引擎其实是对的」的假信号**。

**自动指标漏掉的（人眼才发现）**

| # | 缺陷 | 证据 | 严重度 |
|---|---|---|---|
| 1 | **阿拉伯语 PDF 输出视觉序，未做 bidi 还原** | 逻辑序出现 0 次 / 反转序 65 次；docling 与 pymupdf4llm 均为逻辑序 | **最高**：字不缺但检索、分词、复制全废 |
| 2 | **财报扫描件数字静默错认** | `132,704,932.32`→`132,701,932.32`、`-248,151.42` 负号丢失 | 高：比整段丢失更危险，因为看不出来 |
| 3 | **HTML 路径丢弃行内数学公式** | `需要知道 的質因數`（公式整块消失只留空格） | 中：真值解析器同样剥公式，指标因此对称失明 |

**分数低但引擎是对的（不要据此改代码）**

| 现象 | 例子 | 真实原因 |
|---|---|---|
| `char_sim` 0.59 而词级 `cer` 0.0003 | `sec_vz_10k` | Markdown 表格的 `|` 被算进字符差异 |
| `char_sim` 0.38 | arXiv 三份 | 真值剥了公式、丢了参考文献，引擎照实输出 |
| `cell_f1 = 0`、`table_count_diff +79/+114` | eurlex ×3、wiki ×4、rfc9297、SEC | 真值侧把版面表降级成段落 / 丢弃信息框；RFC 那张「表」其实是页眉 |
| `order_tau 0.53` | `rendered_eurlex_32013r0524_es_p7_tiff` | **真值的分栏顺序是错的**，产物反而对 |

## 二、失败模式归纳（12 类）

按「是谁的问题」分三组。

### A. 引擎缺陷（应建 issue）

1. **RTL PDF 不做 bidi 逻辑序还原** —— 阿语 PDF 全部为视觉序。HTML 路径无此问题
   （`wiki_ar_diabetes` 顺序完全正确），**缺陷精确定位在 PDF 文本抽取层**。
2. **图片 OCR 通道的表格行内读序错乱、数值互换** —— `syn_de_business_jpg` / `syn_en_law_jpg` /
   `syn_fr_it_png` **3/3 复现**（`230 M / Cash flow / 190 M`，法语那份两个季度的值还互换了），
   **docling 同件全部正确**。这是本轮唯一「同题对比下我们错、对手全对」的结构性缺陷。
3. **旋转退化图（`degradation=rotated`）内容腰斩** —— `rendered_cninfo_300513/300817_tiff`
   只保留 46–49% 文本、表格行首标签整列丢失，**同页 docling 保留量是我们的 2.2 倍**，
   说明不是图片不可识别，是版面丢了。
4. **标题判定噪声** —— 图注面板字母（`#### f`、`## a c`）、源文件 XML 名
   （`# L_2019186EN.01005701.xml`）、正文关键词（`##### MUST`）、单字母碎片（`#### ر`）
   被提升成标题；反向还有「标题吞掉正文首句」（`## § 2 Begriffsbestimmungen Im Sinne dieses Gesetzes ist`）。
   两者都污染 outline 与 RAG 分块。
5. **扫描 PDF 通道把正文段落渲染成假列表** —— 两份德语法条的 `(1)`/`(3)` 条款段落
   一律变成 `- ` 列表项。
6. **HTML 路径丢弃行内数学公式**（见上）：38 份 CJK HTML 平均每份留下 104 处 CJK 间空格，
   markitdown 同文档只有 0–16 处。
7. **HTML 路径泄漏隐藏元数据** —— `sec_vz_10k` 产物开头有 1000+ 字符 XBRL 上下文
   （`us-gaap:CommonStockMember…`）。markitdown 同样泄漏，属 HTML 通道共性。
8. **办公文档零标题** —— `egov_jp` 的 docx/html 产物只有 0–1 个 Markdown 标题，
   而官方 XML 里有 57–117 个条标题。源文件确实没有 h 标签/标题样式（markitdown 同为 0），
   属**口径问题居多**，但「一个层级都不给」让下游 RAG 分块无从下手，仍是真实短板。
9. **性能异常** —— `funsd_82200067` 单张 PNG 耗时 **167.8 s**，而同类 `funsd_82253362` 只要 16.7 s，
   相差 10 倍，原因未查。

### B. OCR 后端能力边界（不是版面问题，改不动，但要在文档里说清）

10. **小字号 CJK 整行丢失** —— `govcn` 扫描件丢约 18% 正文、`xfund_ja` 丢 7 处字段；
    与项目已知的 OCR 质量边界一致。对照引擎在同件上多为 0 分，**我们仍是唯一能出结果的**。
11. **低 DPI（150–200）下词位移** —— 个别词被甩到段尾（`Refs [4, 5]` 整块丢、
    法语 `façon` 被移到句末）；**300 dpi 的 jpg 完全没有这个现象**，是可用的下限提示。
12. **符号误认** —— `§`→`$`/`8`（德语法条）、数字 `4`→`1`（财报）、负号丢失、`已`→`巳`。
    docling 在同件上同样错，属共同边界；但**财报数字错认后果最重，报告里单列**。

### C. 真值/指标侧的问题（要修的是 bench，不是引擎）

- `syn_en_it.pptx` / `syn_ja_it.pptx` 的**真值多写了三行源文件里根本不存在的列表项**
  （核实过 pptx 的 zip 内容），拉低了这两份的 char_sim/length_ratio → `make_synthetic.py` 要修。
- `rendered_eurlex_32013r0524_es_p7_tiff` 的**真值分栏顺序是错的**（右栏 5、6 排到了左栏 1 前面）。
- `rfc9297` 的真值把 RFC 页眉 running head 当成了表格，引擎不输出它反而被判 `cell_f1 = 0`。
- `xlsx` 的 Notes 表被真值当段落，`cell_f1` 因此封顶在 0.774。

## 三、三条待确认缺陷的核实结果

夜跑冒烟阶段记录了三条待确认缺陷，抽检逐条核实：

| 缺陷 | 结论 |
|---|---|
| ① 中文 PDF 换行处被塞空格 | **在原生文字层 PDF 上不成立**：72 份 CJK PDF 共 22 处（均 0.3/份），与 pymupdf4llm 22、pdfplumber 21 持平。原先「比 pymupdf 多 8.5 倍」的结论来自**指标 bug**（见文末），已撤回。但 govcn 的**扫描件**上确有整词被劈开（`建立闲置或挪用增 发国债资金问题台账`），那是 OCR 断行，docling 同位置同样有。 |
| ② 表格 → 列表的阅读顺序被倒置 | **原缺陷未复现**（`syn_es_it_docx` 顺序正确、`order_tau = 1.0`）。但发现一条**相邻且更明确**的缺陷：图片 OCR 通道的表格**行内**读序错乱，3/3 复现、docling 全对（见 A.2）。 |
| ③ 列表项渲染成 `- • xxx` 双项目符号 | **未复现**：15 份产物全量扫 `^\s*-\s*[•·▪●○‣]` 命中 0。但本批有真实列表输出的样本只有 1 份，**覆盖力不足，不能判定已修复**，建议在 docx/HTML 多列表样本上复查。 |

## 四、抽检期间发现并修掉的两个指标 bug

两个都会**改变已发布的数字**，因此当场修掉并用 `bench/rescore.py` 重算了全部 3224 条记录
（用已落盘的产物重算，不重跑引擎，几分钟）。

1. **`norm_text` 的 `<[^>]+>`** 会把物理正文里 `q < qc … T > Tc` 之间整段当标签吃掉：
   一份 arXiv 产物归一化后从 61312 字缩到 22268 字，**凭空「丢」了 39044 字**。
   已收紧为「合法标签名开头」。重算后 aimorsel 平均 char_sim +0.006，单份最大 +0.363。
2. **`cjk_inner_spaces` 先把换行折成空格**，于是 `## 背景\n\n一貫性…` 这种**正常段落边界**
   被计成一次命中——一份完全没有行内空格的 pptx 产物被报成 3。这个假阳性
   **系统性偏向「输出结构更少」的引擎**，用它做跨引擎对比会得出反的结论。
   已改为只数行内水平空白；修正后 aimorsel 从 18002 降到 4781，
   **且「PDF 上比 pymupdf 差 8.5 倍」这个结论直接消失**。

教训：**任何「我们比对手差 N 倍」的结论，先去看指标实现**。这两个 bug 都是人工抽检
逼出来的——自动跑批不会告诉你它自己算错了。
